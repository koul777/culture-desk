# Repeatable quality check

Use Node 24 and install dependencies with `npm ci --ignore-scripts`. Install the pinned Chromium once with `npx playwright install chromium` (Linux CI: `npx playwright install --with-deps chromium`).

`npm run quality` runs TypeScript, every `tests/*.test.ts` test, the production Vite build, and all configured desktop/mobile Chromium cases in sequence. The current browser suite has eleven desktop cases (including separate JS/CSS chunk failures, date rollover, and pending-filter export) and one mobile flow. It stops at the first failure and writes durations/status to `test-results/quality-summary.json`. `npm run test:e2e` reruns browser checks against the existing build; rebuild first after changing the UI.

The browser suite starts its own HTTP server on `127.0.0.1:4339` and refuses to reuse an occupied port. It serves `dist/client` and the real published cloud API with 36 clearly labelled TEST records in memory. Only the bootstrap's calendar day is fixed, so default date filters are repeatable. It never reads `.env`, uses the production snapshot, writes a database, or collects upstream data. Browser requests for map tiles receive visibly synthetic OFFLINE QA tiles; unexpected remote requests, API mutations and runtime exceptions fail the check. The server also rejects all outbound `fetch` calls.

Coverage: national bootstrap; pagination and reset; regional search; card/table/map/export result agreement; detail facts; free-price filter; obsolete-request cancellation with completed held-route settlement; search retry; map cancellation/reentry; tile-outage fallback; persistent map JS/CSS chunk failure followed by reload with saved filters and applied styles; low-zoom popup keyboard focus through marker replacement and resize, Escape and reopen; a newer publication with unchanged counts refreshing list and map once; region keyboard dismissal/focus; 375px mobile cards/region/detail/table/map/empty states, horizontal overflow, 44px touch targets including export, hidden duplicate navigation/help with region rules retained in the dialog, a delayed map-search loading label, and linked date-validation messages. Spreadsheet contents are checked after an actual browser download. Chunk failure tests preserve the shared offline and runtime-error guard; they do not suppress arbitrary page errors.

Artifacts are ignored locally: `test-results/e2e/` contains desktop/mobile screenshots and workbook evidence; failures retain screenshots and traces. `playwright-report/` is the HTML report (`npx playwright show-report`). CI uploads both folders for 14 days. Screenshots show synthetic fixtures and synthetic map backgrounds, not live production data. Chromium smoke does not establish Safari/Firefox, real provider availability, live map rendering or 3D GPU quality.

The `Quality` workflow checks PRs and supports manual runs. Repository branch protection must separately require its `quality` job if merge blocking is desired. Main pushes run the same command in the refresh workflow before deployment, so any validation failure prevents that deployment without duplicating the entire check in two workflows.
