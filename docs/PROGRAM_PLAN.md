# Culture Desk · 전국 주요 공연 검색 프로그램

2026-10-18 갱신 · 공개 스냅샷 배포 방식과 현재 코드의 검증·복구 절차를 반영한다. 배포 확인 기록은 각각의 검증일 기준이며, 초기 논의는 `MEETING_NOTES.md`, `IMPLEMENTATION_CONTRACT.md`에 이력으로 보존한다.

## 목적

전국에서 개최되는 주요 공연을 지역과 기간으로 검색하고, 공연장 위치와 실제 건물 자료를 함께 살펴본다. 전시는 제외한다. 로그인·접속 암호·기획 메모·보관함 없이 검색 화면을 바로 연다. 근거 없는 인기 순위나 임의의 행사·건물 정보는 제공하지 않는다.

## 사용 흐름

1. 처음에는 체크된 지역 없이 전국의 저장된 공연 자료를 조회한다. 기본 기간은 이번 달 1일부터 오늘로부터 3개월 뒤까지다.
2. 지역 선택에서 시도와 시군구를 체크한다. 미선택·전체 선택은 전국, 일부 체크는 해당 지역만 조회한다.
3. 공연 카드를 확인하고 기간·장르·검색어·상태·관람료·연령·출처로 좁힌다.
4. 같은 조건으로 카드·표·지도 보기를 전환한다. 지도는 상단 버튼·별도 메뉴 또는 `/#map` 주소로 바로 연다.
5. 실제 공연장 마커에서 공연 목록·상세 또는 **공연장 3D로 보기**를 연다. 건물 도형·높이 확보 상태에 따라 입체·평면 외곽·위치만 구분해 표시한다.
6. 상세에서 제공된 일정·가격·출연진·주최·원문을 확인하고 검색 결과를 엑셀로 받는다.
7. 웹의 데이터 연결에서는 자료 기준 시각과 전국 자동 갱신 결과를 확인한다. 다른 기간의 수동 수집·상세 보충은 별도로 실행한 로컬 프로그램에서 한다.

## 화면과 구현 상태

| 화면 | 구현 기능 |
| --- | --- |
| 공연 검색 | 전국 230개 지역 복수 체크, 지역명 검색, 전체 선택/해제, 검색 조건, 카드 기본 보기 |
| 표·2D 지도 | 같은 조건의 표와 실제 공연장 위치, 팝업 공연 목록·상세·3D 연결 |
| 공연장 3D | 브이월드 설정 시 제공 건물 표시, 미설정 또는 전환 시 Cesium 외곽 모형. 필요한 뷰어만 지연 로딩하고 도형·높이 근거를 구분 |
| 공연 상세 | 제공기관의 날짜·장소·가격·연령·공연 시간·출연진·주최·연락처·원문 |
| 데이터 연결 | 웹은 공개 자료·자동 갱신 상태 조회. 로컬은 두 출처 설정, 수동 수집·상세 보충·중단·재개 |
| 엑셀 | 검색 결과와 출처·수집 범위·부분 결과 여부를 담은 조회 근거 |

운영 사이트 이용에는 API 신청이 필요 없다. 별도 로컬 설치와 자동 수집 구성에는 공연 API 인증키를 준비한다. Cesium 외곽 모형에는 지도 인증키가 필요 없으며 브이월드 제공 건물 지도에는 별도 키·도메인 설정을 사용한다. API 연결 검증 기록은 [구현 보고서](IMPLEMENTATION_REPORT.md)의 검증일 기준이다.

## 전국 자료 수집

전국 카탈로그는 KOPIS 공식 검색 API 기준 **230개 지역·16개 시도 그룹**이다. 일부 일반구를 가진 도시는 시 단위로 제공한다. 기존 7개 도시 ID와 좌표는 유지한다.

2026-10-01~2027-01-16 범위의 **230개 지역 × 2개 출처, 총 460개 지역·출처 조합에서 목록·상세 단계가 완료**됐다. **5,600행·200개 지역이 2026-10-16 최종 집계**이며 전체 공연의 상세·좌표를 확보했다. 독립 예약 작업으로 매일 범위를 이동해 갱신하고 실패하면 체크포인트부터 재개한다. [자동 갱신 운영](AUTOMATIC_REFRESH.md) 초기 7개 도시 103행은 이전 검증 이력이다.

KOPIS와 문화포털의 원본 행을 유지하므로 서로 같은 공연이 포함될 수 있다. 합계를 고유 공연 수나 인기 순위로 표현하지 않는다. 전시는 제공기관 분류로 제외하고 불명확한 항목은 검토 대상으로 남긴다. 관람료는 관객 입장 가격이다.

제공기관이 반환한 좌표만 실제 공연장 위치로 사용한다. 좌표가 없으면 도시 중심을 공연장으로 대체하지 않으며 해당 공연은 목록에서 계속 조회된다. 지도 조회는 현재 목록 페이지와 별도로 조건에 맞는 항목을 가져오되 최대 10,000행·3 MiB 한도와 잘림 여부를 표시한다.

## 공연장 건물의 근거

현재 실제 OSM 도형을 확인해 보관한 공연장은 3곳이다.

- 원주 백운아트홀은 실제 도형과 OSM 2층 정보를 사용한다. 표시 높이 **6m는 층당 3m에 따른 추정**이며 실측값으로 표시하지 않는다.
- 안동문화예술의전당과 여수 예울마루는 실제 도형의 평면 외곽을 표시한다. 높이는 미확인이다.
- 다른 공연장은 허용된 Overpass 제공처에서 동적으로 확인한다. 도형이 없거나 조회가 실패하면 위치만 표시한다. 임의의 가까운 건물이나 높이를 생성하지 않는다.

건물 도형은 실제 공연장 좌표 포함 여부와 이름 증거로 연결한다. 다른 이름의 건물이거나 여러 건물 중 구분할 수 없으면 표시를 보류한다. 출처·확인 시각을 보존하고 확인된 원자료 캐시에는 유효기간을 둔다. 현재 구성은 도시 전체의 실사 3D 또는 정밀 지형 서비스가 아니다.

## 실행·저장·게시

React/Vite/TypeScript 화면, Leaflet 2D 지도, CesiumJS·브이월드 공연장 화면, Fastify 서버를 사용한다. 3D 관련 자산은 해당 화면을 열 때 불러온다. 로컬은 SQLite와 Windows 실행기를 사용한다. 공개 웹은 Vercel의 정적 화면·Node.js API가 배포에 포함된 공개 JSON 스냅샷을 읽으며 외부 DB 서비스에 의존하지 않는다.

GitHub Actions가 두 API를 수집하고 SQLite에서 감사·병합한 뒤 공개 스냅샷을 만든다. 수집 완료와 배포 성공은 별도로 기록한다. 배포가 실패하면 같은 날짜의 완료된 자료를 재수집하지 않고 배포를 재시도한다. 체크포인트와 배포 성공 기록은 운영·미리보기 브랜치별로 구분하며, 배포 전 공통 품질 검사를 통과해야 한다. 세부 조건과 복구 절차는 [자동 갱신 운영](AUTOMATIC_REFRESH.md)을 따른다.

공개 스냅샷의 읽기 전용 서버 객체를 재사용하며, 반복 JSON 조회는 스냅샷별 최대 32개·본문 16 MiB까지 저장한다. 한국 날짜가 바뀌면 날짜 의존 검색과 상태 응답을 다시 계산한다. 브라우저·외부 캐시는 기존 no-store 정책을 유지하고, 엑셀·외부 건물 조회·DB 장애 대체 응답에는 이 응답 캐시를 적용하지 않는다. 이전 PostgreSQL 방식은 명시적으로 설정하는 호환 코드로만 남아 있다.

전국 일괄 수집은 별도 SQLite에서 진행하고 체크포인트를 감사한 뒤 운영 DB에 병합한다. 기존 공연 ID·최신 상세·개인 자료를 보존하고 반복 게시로 수집 이력을 중복시키지 않는다. 새 미완료 수집이 과거 완료 이력에 가려지지 않도록 완료 범위를 판단한다. 로컬 게시 시 실행 중 DB 잠금을 확인한다.

공개 웹은 검색·지도·공연장 도형·상세·엑셀을 제공하며 수집·변경 API는 열지 않는다. 개인 메모와 관심 표시는 공개 스냅샷과 내보내기에서 제외하며 원본 DB에서는 삭제하지 않는다. 공연 API 키는 수집 환경에서만 사용한다. 브이월드 키는 브라우저 SDK용이므로 등록 도메인으로 제한한다. 로컬·명시적 DB 호환 모드의 변경 요청 검증과 저장 실패 롤백은 유지한다.

수집은 31일 구간·페이지·상세 작업 단위로 기록하고 제한적으로 재시도한다. 출처별 최대 4개 작업과 실제 HTTP 시작 간격 350ms를 유지하며, 같은 공연장 조회는 provider의 캐시를 공유한다. 인증·호출 한도 오류는 보류하고 미완료 작업은 후속 예약에서 재개한다. 운영 절차와 제한은 [Vercel 운영](VERCEL.md)을 따른다.

## 검증과 남은 확인

2026-10-16 운영 검수에서 검색·지역 선택·지도·3D·상세·엑셀을 확인했다. 당시 원주 백운아트홀의 실제 도형과 추정 높이, 3D 닫기 후 검색 복귀, 데스크톱·모바일 화면을 검사했다. 현재 코드의 공통 검증 명령은 `npm run quality`이며 타입 검사·자동 테스트·빌드·격리된 브라우저 검수를 순서대로 수행한다. TEST 자료를 사용한 검수는 현재 외부 지도 제공처의 실제 접속 성공을 의미하지 않는다.

남은 자료 검증은 다음과 같다.

- 새 자동 갱신 실행마다 목록·상세·좌표·완료 범위를 감사하고 자료 기준 시각 확인
- 새 복구 절차를 운영에 반영할 때 GitHub 실행 결과와 실제 배포 스냅샷 일치 확인
- 좌표·건물 도형·높이가 없는 공연장의 상태를 숨기지 않고 안내
- 공개 건물 제공처가 정상인 경우에만 실제 도형 범위를 추가 확보

위 자료 검증이 끝나기 전에는 모든 상세정보·전국 모든 공연장 3D 확보가 완료됐다고 표시하지 않는다.
