## 성능과 데이터 일치

저장된 공개 자료 **5,649행**을 같은 입력으로 사용했다. 다른 팀 빌드·테스트를 멈추고 변경 전·후를 순서대로 실행했다. 다음 값은 같은 요청을 30회 반복한 중앙값이며, 변경 후는 **프로세스 내부 응답 캐시 적중**이다. 네트워크 전송, 브라우저 렌더링, 서버 프로세스 시작 시간은 포함하지 않는다.

## 검증과 재현

`npm run quality`는 타입 검사 → 전체 자동 테스트 → 프로덕션 빌드 → 격리된 Chromium 브라우저 검수를 실행하고 첫 실패에서 멈춘다. 브라우저 최초 준비는 `npx playwright install chromium`이다. 검사 결과는 `test-results/quality-summary.json`에 기록된다.

브라우저 검수는 실제 공개 API 처리 코드와 TEST 자료를 사용한다. 검색 조건 변경, 페이지 초기화, 카드·표·지도·엑셀 일치, 상세·키보드 닫기, 지연 요청 취소, 실패 후 재시도, 지도 타일 장애, 375px 모바일 넘침·터치 영역·날짜 오류를 확인한다. 지도 배경은 합성 타일이며 현재 외부 지도 제공처의 성공을 의미하지 않는다.

전체 검증에서 **268/268 자동 테스트·타입 검사·빌드·브라우저 6/6 시나리오**가 통과했다. 검사 도중 추가된 복구 사례 1개는 별도로 통과했으며, 마지막 모바일 CSS 변경 뒤 타입 검사·빌드·브라우저 6개 시나리오를 다시 확인했다. 확인한 서로 다른 자동 테스트는 총 269개다.

이번 과정에서 응답 본문 타입 오류와 브라우저 검수 선택자 문제를 발견해 수정했다. 탐색적인 검사 실패를 삭제하거나 전체 통과로 간주하지 않았으며, 최종 검사와 변경 뒤 필요한 추가 검증 기록을 별도로 보존한다. [검증 요약](verification/team-20261018/qa-summary.json) · [전체 검사 로그](verification/team-20261018/quality.txt) · [최종 변경 추가 검증](verification/team-20261018/quality-supplement.txt).

## 운영 반영 시 확인할 사항

이번 변경은 로컬 코드와 검증 결과까지다. 운영 배포, GitHub 워크플로 실행, 외부 공연 API 재수집은 하지 않았다. 실제 수집 주기의 시간·호출량과 새 워크플로의 운영 성공은 배포 후 확인해야 한다.

배포 전 공통 검증이 실패하면 배포를 중단한다. 배포만 실패하면 다음 예약이나 재실행에서 같은 날짜의 완료한 자료를 사용한다. 스냅샷·커밋·환경이 일치하는 성공 기록이 없으면 재배포한다. 배포는 성공했지만 최종 상태 업로드가 실패한 경우에도 성공을 추정하지 않고 다시 배포하도록 했다. 구체적인 복구 파일과 절차는 [자동 갱신 운영](AUTOMATIC_REFRESH.md)에 있다.

기존 미추적 영상·화면·연구 자료는 보존했고, 운영 스냅샷과 로컬 원본 DB를 변경하지 않았다. 전체 구조 교체나 기존 DB 호환 코드 삭제는 이번 범위에 포함하지 않았다.
