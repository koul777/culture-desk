# 공연 리서치 프로그램 설계회의 결정 기록

일시: 2026-10-16 · 방식: 독립 검토 + 상대 의견을 전달한 교차 검토 + Codex 최종 정리

Codex가 주관하고 설치된 Claude Code CLI와 Cursor Agent CLI가 실제로 응답했다. Orca를 사용한 회의는 아니다. 두 CLI는 비대화형으로 실행했으며 검토문을 프롬프트로 전달했다. Claude는 도구 비활성화, Cursor는 읽기 전용 질의 모드를 사용했다. 프로그램 구현이나 API 인증키 호출은 수행하지 않았다.

## 참여와 증거

| 참여자 | 역할 | 원문 |
| --- | --- | --- |
| Codex | 명세 확인, 최종 범위·완료 기준·설계 통합 | [1차 검토](reviews/codex-round1.md) |
| Claude Code | 기획자 흐름, MVP 범위, 데이터 오해 방지 | [1차](reviews/claude-round1.md) · [2차](reviews/claude-round2.md) |
| Cursor Agent | 로컬 구현, 수집·복구 구조, 테스트 | [1차](reviews/cursor-round1.md) · [2차](reviews/cursor-round2.md) |

실행 시각·종료 코드·결과 상태는 같은 폴더의 .receipt.json 파일에 보존했다. Claude 실행 결과가 보고한 모델은 claude-opus-5-5다. Cursor 결과에는 모델 ID가 없어 확정하지 않는다. 역할만 나눈 가상 회의가 아니라 각 도구의 실제 의견을 다른 도구에 전달한 검토다.

## 검토로 바뀐 결정

| 쟁점 | 실제 의견 | 반영 |
| --- | --- | --- |
| 데이터 범위 | 양쪽 1차는 KOPIS부터 구현 제안. Codex는 문화포털도 정식 범위에 포함 | 내부 M1과 사용자 V1 구분. V1은 두 API 실제 검증 |
| 화면 범위 | 양쪽 모두 비교 페이지·카드 등 후순위 제안 | 검색 표·상세·관심 목록·메모·엑셀 우선 |
| 상세 필터 | Cursor 1차는 상세 호출 최소화. Codex가 상세 미수집의 필터 누락 지적 | 보충 큐·부분 결과·남은 건수·미상 구분. 2차에서 양쪽 동의 |
| 0건 표시 | Claude가 도시·기간·출처별 수집 상태와 등록 0건 구분 제안 | 검색·연결·엑셀에 동일 상태 |
| 가격 의미 | Claude가 관람료와 제작비 혼동 지적 | 관람료 원문, 무료·유료·미상, 예산성 집계 제외 |
| 수집 복구 | Cursor가 DB 큐·실패 구간 재시도 제안 | 단일 워커·실행/세부 작업 분리·체크포인트 |
| 엑셀 | Claude가 조회 근거 시트 제안 | 목록과 조회 근거 2개 시트 |
| 중복 | 양쪽 자동 병합 보류 동의 | 원본 유지·출처별 건수·순회공연 보호 |
| 장기 수집 | Claude는 한도 대기, Cursor는 작업량 안내 제안 | 한도·작업량 확인, 보류·재개, 근거 없는 시간 추정 금지 |

## 조건부 승인과 최종 선택

Claude와 Cursor는 2차에서 공통 기술 구조와 주요 기능에 동의했고 실제 API 호출·한도·필터 검증을 조건으로 승인했다. 검증 전 연결 완료로 보고하지 않는 조건을 완료 기준에 반영했다.

남은 차이는 Codex가 다음과 같이 정리했다.

- **문화포털 상세 깊이:** Cursor는 목록 중심의 좁은 V1도 제안했다. 최종안은 실제 제공 필드 차이는 허용하되 관람료 필터에 필요한 상세 보충·미상 처리까지 양쪽에 적용한다.
- **원문 대조 개수:** Claude는 출처별 10건, Cursor는 KOPIS 10건·문화포털 3건을 제안했다. 최종안은 출처별 최소 10건이다. 자료가 적으면 전건 확인하고 사유를 기록한다.
- **전시 필터의 응답 필드:** 교차 검토 후 Codex가 명세를 추가 확인했다. D000은 분야 조회 요청 코드이고 지역 목록에는 realmName이 명시되어 있다. 목록에 realmCode가 있다고 가정하는 구현을 피한다.
- **사실 정정:** Claude 2차의 ‘사용자가 두 API를 주었다’는 표현은 정확하지 않다. 사용자는 문화포털 링크를 제공했고 KOPIS는 Codex가 보완 데이터로 제안했다.

이 세부 선택은 검토 의견을 바탕으로 Codex가 결정했다. 모든 구현 세부사항을 세 참여자가 독립적으로 실증했다는 의미는 아니다.
