# 전국 공연 실수집 도구

프로젝트 루트에서 Node 24로 실행합니다. `.env`의 기존 KOPIS·문화포털 키를 읽으며 키 값을 인자나 로그에 출력하지 않습니다.

매일 실행하는 CI는 `NATIONAL_FROM`, `NATIONAL_TO`, `NATIONAL_BATCH`, `NATIONAL_DIRECTORY`로 기간·배치 ID·독립 작업 디렉터리를 지정할 수 있습니다. 미지정 시 아래의 최초 수집값을 사용합니다. 날짜는 실제 `YYYY-MM-DD`와 시작≤종료를 검증하고 배치 ID는 영숫자로 시작하는 영숫자·`_`·`-` 1~100자로 제한합니다. 감사·재시도·좌표 보강도 같은 환경 설정을 사용합니다. 새 배치는 빈 독립 DB에서 시작하고, 체크포인트 복원은 같은 배치의 미완료 작업을 재개할 때 사용합니다. 이전 배치의 완료 DB를 새 배치에 그대로 넣으면 이미 완료된 동일 기간이 재수집되지 않을 수 있습니다.

```powershell
node --import tsx scripts/collect-national.ts
```

이 배치는 2026-10-01~2027-01-16을 전국 카탈로그의 230개 지역과 두 출처에서 조회합니다. 31일 이하 네 구간과 모든 후속 페이지를 수집하고, 전시를 분류해 검색에서 제외한 뒤 공연 상세와 KOPIS 공연장 정보를 보강합니다. 요청은 출처별 최소 350ms 간격, 동시에 최대 4건입니다. 각 출처에 전용 worker 4개를 배정해 한쪽의 긴 대기열이 다른 쪽 요청을 막지 않습니다. 같은 공연장의 KOPIS 응답은 provider 캐시를 공유합니다.

기존 앱 DB를 열거나 덮어쓰지 않습니다. 독립 DB는 `data/national-20261001-20270116/collection.db`입니다. 프로세스 잠금으로 중복 실행을 막고, 같은 명령을 다시 실행하면 동일 출처·지역·기간의 완료 작업을 재생성하지 않고 남은 대기 작업을 처리합니다. 인증·쿼터로 정지한 작업은 자동 재개하지 않습니다.

`progress.json`은 10초마다, `checkpoint-<timestamp>.db`는 60초마다 기록합니다. 체크포인트는 SQLite `VACUUM INTO`로 만든 일관된 사본입니다. 가져오기는 진행 중 DB 대신 `progress.json`이 가리키는 체크포인트를 사용합니다. 모든 목록이 완료돼도 상세 대기가 있으면 전체 완료로 표시하지 않습니다. 0건 지역도 네 날짜 구간을 실제로 조회한 작업 기록이 남습니다.

실행 중 `data/national-20261001-20270116/stop.request` 빈 파일을 만들면 10초 이내 요청을 취소하고 최종 체크포인트를 저장한 뒤 안전하게 종료합니다. 다시 실행하기 전에 이 정지 요청 파일을 제거해야 합니다. 진행 보고의 요청 수는 현재 프로세스에서 발생한 횟수이며 재시작 전 호출까지 합한 누계가 아닙니다.

```powershell
node --import tsx scripts/audit-national.ts
node --import tsx scripts/publish-national.ts <checkpoint.db> national-20261001-20270116
```

감사는 최신 체크포인트의 무결성, 230×2 수집 작업, 날짜 구간, 목록·상세 완료의 일관성을 검사하고 `audit.json`에 지역별 결과를 남깁니다. 미완료 또는 검사 실패 시 종료 코드가 0이 아닙니다. 자료 수는 두 출처의 항목 수이며 동일 공연이 양쪽에 등록됐을 수 있습니다. 조회 0건은 지정 기간과 이 두 API의 결과를 의미합니다.

상세 API가 일시 HTTP 400을 반환했다가 동일 요청에서 정상 응답한 실제 사례가 있었습니다. 실패 항목 진단 및 한정 재시도는 다음과 같습니다.

```powershell
node --import tsx scripts/diagnose-national.ts <task-id>
node --import tsx scripts/retry-national.ts
```

진단은 해당 작업 하나를 실제 API에서 다시 읽고 DB는 수정하지 않습니다. 재시도는 연결 오류로 실패한 작업만 10초 뒤 대기 상태로 돌리며, 완료·실행 중 작업과 인증·쿼터·스키마 오류는 건드리지 않습니다. 작업당 추가 복구 횟수는 2회로 DB에 저장합니다. 그래도 실패한 결과는 완료로 바꾸지 않습니다.

모든 수집 작업이 끝난 후 선택적인 공연장 조회 오류로 빠진 좌표는 다음 명령으로 다시 확인합니다.

```powershell
node --import tsx scripts/enrich-national-locations.ts
node --import tsx scripts/audit-national.ts
```

실행 중인 collector와 같은 잠금을 사용하므로 동시에 DB를 열어 작업 상태를 초기화하지 않습니다. 정확한 KOPIS 공연장 ID별로 대표 공연을 재조회하고, 공식 응답의 공연장 ID와 좌표를 검증한 뒤 같은 ID의 누락 자료만 보강합니다. 좌표를 임의 추정하지 않으며, 확인되지 않은 공연장은 `locationEnrichment.unresolved`에 남습니다. 보강 후 새 체크포인트와 진행 보고를 저장하므로 증분 배포에도 동일하게 반영됩니다.
